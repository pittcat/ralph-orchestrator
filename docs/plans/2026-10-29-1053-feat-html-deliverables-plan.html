目标范围接入设计实施单元验收完成标准

Goal Capsule

Objective：用户能从全部 preset 和指定 operator skill 获得完整、易读、离线可打开的 HTML 交付物；不同执行环境使用同一套明确的生成指导。

Means：移植 Effective HTML 指导，入口显式绑定，业务 agent 自己生成页面。用户要求与项目硬规则优先，其后依次为业务契约、HTML 交付契约、专项指导、视觉指导。加载或验证失败不得宣称交付完成。实施者负责代码、文档同步与验证；本计划不授权启动 loop 或发布页面。

Product Contract

Problem Frame

现有最终 MD 报告不利于层次阅读；多份同名 skill 和隐式选择又会使 HTML 生成规则漂移。

Summary

全部 preset 的人类可读最终文档改为 HTML；diagnosis、author、discovery 共享同一指导源。内容规则继续由原入口负责，HTML 指导仅负责表达与交付。

Requirements

  • R1. 逐项覆盖 presets/ 内 builtin、模板及参考变体的最终交付角色，包含成功、失败、阻塞路径；不能只按 reporter 名称筛选。没有最终报告的入口明确登记“不适用”及理由，不新增业务阶段。
  • R2. 覆盖 ralph-run-diagnosis、ralph-preset-author、ralph-task-discovery；author notes 的 HTML 消费同步到 preset-review。Discovery 保留经过 validator 的 YAML brief 作为机器交接物，同时生成 HTML 阅读视图。
  • R3. 每个入口明确绑定报告或计划指导，列出必读文件、可选指导的触发条件、输出路径及停止条件；禁止全局搜索同名 skill 替代指定版本。
  • R4. 最终 HTML 单文件离线可读，真实内容存在于语义 HTML 正文，保留全部结论、证据与未决事项；文本转义，目录和控件可用，宽窄屏及打印可读。

Scope Boundaries

不转换全部内部 MD 证据和执行计划，不改 YAML/JSON 机器契约，不批量转换历史报告，不增加设计 hat、通用渲染平台或公开发布流程。未来由 author 新建的 preset 同样遵循 R3。

Planning Contract

Key Technical Decisions

KTD1. 显式绑定，有限选择。业务入口指定指导组合；报告使用 html、design-artifact、documents-and-presentations，计划使用 html-plan、design-artifact。数据比较及关系解释分别按条件加载 charts-and-data、diagrams；另外三项仅在明确适用时加载。(session-settled: user-approved — chosen over 全局自动挑选 skill: 防止误选与业务流程切换。) 对应 R3。

KTD2. 一份源，两种分发。新增 skills/ralph-html/，容纳薄的交付规则及带来源、版本和许可记录的 Effective HTML 文件。operator 安装携带完整目录；loop 侧从该源构建 namespaced 内置按需 skill，并把辅助引用转换为明确加载名。复用现有 skill load，无新增 CLI；不依赖用户 HOME 或源码 checkout。引用映射须完整，不静默采用同名外部副本。

KTD3. 业务权限不转移。原 hat 决定证据、结论和事件，HTML 指导不启动其他工作流；原 content template 改为内容清单，视觉布局由内容决定。(session-settled: user-approved — chosen over 固定页面模板和额外设计 hat: 保留表达自由及现有责任边界。) 对应 R1–R4。

Skill 清单、位置与用途

共 8 份指导：1 个 Ralph 接入 skill，加 7 个 Plannotator Effective HTML skill。下列是计划中的仓库位置，实施前尚不存在；用户已安装的参考源位于 ~/.agents/skills/<名称>/SKILL.md 和 ~/.claude/skills/<名称>/SKILL.md。以核实后的上游版本为准，禁止从多个安装副本各自复制形成多个维护源。

指导计划中的维护源目的与调用条件
ralph-htmlskills/ralph-html/SKILL.md新增的 Ralph 入口：规定业务权限、必读指导、离线交付、检查与失败处理；所有 HTML 交付入口必读。
htmlskills/ralph-html/vendor/html/SKILL.md通用 HTML 报告工作流；preset 报告及 diagnosis 使用。
design-artifactskills/ralph-html/vendor/design-artifact/SKILL.md视觉层级、排版、配色与可访问性；报告和计划都使用，不执行其公开发布流程。
html-planskills/ralph-html/vendor/html-plan/SKILL.md保留决定、依赖与验收条件的计划或方案；author 和 discovery 使用，规划类 preset 按交付性质绑定。
html-diagramskills/ralph-html/vendor/html-diagram/SKILL.md表达拓扑、流程或因果；仅当关系图确有助于理解时加载。
big-pics-little-wordsskills/ralph-html/vendor/big-pics-little-words/SKILL.md以图辅助解释；仅明确需要直观说明时使用，不删减必要证据。
html-wireframeskills/ralph-html/vendor/html-wireframe/SKILL.md比较低保真界面结构；仅交付物确实包含界面结构探索时使用。
html-prototypeskills/ralph-html/vendor/html-prototype/SKILL.md验证界面或交互流程；仅交付物确实需要原型时使用。

另保留 skills/ralph-html/vendor/html/references/ 的 5 份上游参考文件，它们不是额外的独立 skill。operator 安装整个 ralph-html 目录；loop 编译时从同一维护源注册 8 个命名空间化按需入口，并为必要参考文件建立明确加载映射。实际安装目录取决于 skills/install.py 的目标配置；不得假定用户 HOME 路径存在。

绑定实例：普通 reporter 依次读取 Ralph 入口、html、design-artifact 和文档参考；diagnosis 相同，必要时补充图表或图解；author 与 discovery 读取 Ralph 入口、html-plan 和 design-artifact。业务证据、裁决及交接仍由各自的原 hat 或 operator skill 负责。选择器、精确注册名和引用映射在 U1 清单中逐一列明，并在 U2 验证，而不是让 agent 猜测路径。

High-Level Technical Design

同一指导源 → operator 安装目录 / Ralph 内置 skill → 当前业务 agent → HTML 文件 → 原有交付路径

运行顺序：读取业务证据 → 加载绑定指导 → 编写 HTML → 检查内容及页面 → 交付路径。循环内继续使用现有 policy-check、emit 和 report_path；operator 保持各自原交接规则。

Assumptions / Risks

浏览器不可用时保留 HTML 草稿并标明视觉未验证；本次纳入的最终交付入口均停止完成声明，按原失败或停止流程报告环境缺口。移植前置条件：U1 必须核对已安装文件对应的上游版本与许可；当前尚未核实，未确认前不得进入 U2 的嵌入与分发。现有自定义 skill 可覆盖内置名称，因此新内置指导须校验其受控来源，不能仅靠命名避免覆盖。

Approach / Verification

Approach / Test scenarios / Verification

按 KTD2 从共享源嵌入独立按需指导，明确引用加载名；以现有 registry 和 CLI 为接入点，限定所需 hat 可见性，给受控名称增加来源检查。长文件按职责拆分，单源码文件不超过 5000 行。

Approach / Test scenarios / Verification

按 U1 清单迁移 instruction、最终内容模板及路径消费者；逐项检查 schema、终态文件检查、交付展示，保持原事件拓扑。新路径不得残留硬编码 MD 消费假设。

  1. 成功、失败、阻塞结果均先写正确 HTML，再交付一致的 report_path。
  2. 文件缺失或路径不一致时，原完成门禁继续拒绝；恢复不能改写原结论。
  3. 材料加载失败时不宣称完成；完成型入口真实运行验证，参考模板按结构化配置检查。

执行全部 preset lint/parity 与真实 runtime scenario；不新增包含文本或整文件字节相等断言。

U4. Operator skill 接入与完整验收

Goal：

R2–R4、KTD1–KTD3

U2、U3

Approach / Test scenarios / Verification

各 skill 在原交付阶段读取固定 HTML 指导；同步 diagnosis 元数据读取、author notes 消费和 discovery 阅读视图，不改变业务裁决。

  1. Discovery 的未决/blocked 状态在 HTML 中如实呈现，YAML validator 仍阻止交接。
  2. Author 的 AAF、Payload Contract 可从 HTML 正文完整读取并交给 review。
  3. Diagnosis 缺失证据不会被隐藏；含 HTML 特殊字符的日志按文本显示。
  4. 浏览器离线检查报告、计划两类样本：宽窄屏、键盘、折叠、打印及控制台；无工具时记录未验证。

同步 crates/ralph-core/data/ralph-tools*.md 通用加载指南、author/review 本地 references、AGENTS.md builtin 描述及 zsh 补全；安装并验证补全加载。所有新增运行能力说明遵守 agent/operator 边界。

Verification Contract

实施阶段先做二进制安装与真实 CLI smoke，再运行受影响 nextest 子集。preset 改动必跑 cargo nextest run -p ralph-cli --bin ralph -- preset_lint、cargo nextest run -p ralph-core -- preset_lint、cargo nextest run -p ralph-cli --bin ralph -- presets。测试子进程清理项目列出的 agent runtime 环境变量。

Python 检查使用 .venv；最终运行 ./scripts/run-tests.sh 和 scripts/check-cli-doc-drift.sh，并检查相关 CLI help、prompt 可见性及浏览器样本。计划阶段不运行测试。

Definition of Done

入口清单无遗漏；指导源和引用可追踪；全部适用入口交付 HTML；机器交接与失败门禁有效；文档、schema、补全同步；验证证据完整，删除试验代码与临时产物。历史 MD 无需迁移。
