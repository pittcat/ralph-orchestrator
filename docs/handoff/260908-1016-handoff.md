# 关键决策和理由

1. **topic 方案 (b)**：新增 per-unit `forge.unit.*` 族（executed/execution_failed/reviewed/verified/verification_failed/integrated），wave 路径不动；verdict 用 `ACCEPTED/REJECTED`。理由：不动 wave 执行面，回归面最小。
2. **runtime_driven 抑制只在 `dag` 生效**：`dag_shadow` 不抑制（shadow 只观察，wave 执行面照常）；`wave` 直接 fail-closed 拒绝。理由：shadow 模式的定义就是「legacy 执行 + DAG 旁路观察」，抑制会破坏观察对象。
3. **triggers/publishes 保留声明**：作为 job 模板的输入/输出 topic 文档，保持 lint 拓扑闭合；Phase C 退休 forge-dispatcher 后再清理。代价：WAC lint 教学推迟到 Phase C。
4. **spawn 架构**：DAG job 复用 `pty_kernel`；prompt = hat instructions + DAG preamble；env 用 `runtime_job/environment.rs` 的 DagEnvPolicy allowlist；身份注入 `RALPH_DAG_UNIT_KEY/JOB_ID/ATTEMPT`；per-job events 文件 + merge 回主账本（比照 `FileEventMergeSink`）。
5. **`forge.exec.development.done` 沿用**，dag 模式 emitter 换 runtime：幂等键存 DAG store，用 `append_supervisor_coord_event` 形态（append+system_injected+不推进 cursor，参考 `wave/dispatcher/coordination.rs:844`）。
6. **integration gate**：`real_orchestrator` 空 gate 命令集 fail-closed（`dag_scheduler/integration.rs` 约 287-293 行），必须从 Unit metadata 的 `tests` 字段推导真实 targeted gate 命令。
7. **inner.rs 接缝纪律**：`crates/ralph-cli/src/loop_runner/inner.rs` 当前 4887 行，**不得净增长**（5000 行硬规则）——新增前先拆旧 helper（Step 4 已示范：拆出 `termination_diagnostics_support.rs`）。
