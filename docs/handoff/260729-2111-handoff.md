## 重要注意事项（gotchas、约束、环境变量等）

### 测试入口（HARD RULE）

- 必须用 `cargo nextest run` 或 `./scripts/run-tests.sh`。
- 禁止裸 `cargo test -p ralph-cli` 或 `cargo test -p ralph-cli --bin ralph`。
- `cargo-nextest` 版本钉在 `mise.toml` 的 `0.9.140`。
- 默认走并发；BDD scenarios 单独跑 `cargo nextest run -p ralph-core --test scenarios -- <name>`。
- 全量入口 `./scripts/run-tests.sh` 会拆 phase 1（num-cpus 并发）+ phase 2（3 个 race-sensitive 测试串行隔离）。
- flake 兜底 `RALPH_BASELINE_SERIAL=1 ./scripts/run-tests.sh` 仅作 flake 兜底，不是默认路径。

### Hat env scrub（HARD RULE 5）

写测试 spawn `ralph` CLI 时必须 scrub `RALPH_CURRENT_HAT` / `RALPH_CURRENT_LOOP_ID` / `RALPH_EVENTS_FILE` / `RALPH_WAVE_WORKER` / `RALPH_TRIGGERED_HAT` / `RALPH_HATS_SOURCE` / `RALPH_CONFIG`。ralph-cli 集成测试统一用 `crates/ralph-cli/tests/common/mod.rs` 的 `common::ralph_bin()` / `scrub_agent_runtime_env`。

### Worktree 复用（HARD RULE 3）

`ralph run --worktree` 必须显式带 `--plan <plan.md>` 或 `--worktree-name <name>`。禁止 agent 自行 `EnterWorktree` / `git worktree add`。

### Hat instructions 视角（HARD RULE 4）

`instructions:` 是写给「该 hat 在自己那一轮 activation 里的 agent」看的，不是给 preset 作者看的。`event_loop.execution_mode: isolated` 是唯一执行模式。每个 activation 是隔离的进程级单元，hat 只能通过 `RALPH_CURRENT_HAT` 等 env + `ralph tools task <cmd>` / `ralph emit` / `ralph wave emit` 通信，不能读 `.ralph/events.jsonl` / `.ralph/supervisor.db` / `.ralph/loops.json`。

### AGENTS.md / CLAUDE.md 同步

两文件必须 byte-identical。修改其中一个后必须 `cp` 同步。

### Plan 残留文件不进 git

`.ralph/review/<plan-id>/{residuals*.md,scratch/,draft/}` 禁止 commit。

### AI skill guide 同步

`crates/ralph-core/data/*.md` 必须随功能演进保持同步。新增/删除/重命名 ralph CLI 子命令、新增/修改 event 类型、新增/修改 task/memory 工作流、新增/修改预设/配置字段、新增/修改 wave/loop/inspect/doctor 等行为、新增/修改需要 agent 在 loop 中使用的工具或输出格式，都必须同步。

### Preset operator skills 同步

`skills/ralph-preset-author`、`skills/ralph-preset-review`、`skills/ralph-preset-common/references/` 必须随 Ralph 能力演进保持可审计。

### Preset 测试规则（HARD RULE）

不要新增只校验 preset YAML / hat instructions / prompt 文案是否包含某段文本的测试。优先测试结构化语义：`RalphConfig::parse_yaml`、hat `triggers` / `publishes`、`event_policy.schemas`、`required_fields`、preset lint findings、BDD scenario 或真实 runtime path。

### 中文输出（HARD RULE）

所有面向人类的输出（计划文档、设计文档、需求文档、实施计划、任务文件、报告、总结、注释说明、代码 review 意见、PR 描述）都必须使用中文撰写。文件名、代码字符串字面量、代码注释中的技术标识符、命令行输出块不受影响。
