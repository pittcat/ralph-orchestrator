# Preset Skill 依赖合同需求

状态：需求已确认，待方案设计与实现。本文是后续设计的输入，不代表能力已实现。

## 目标与问题

Preset 需要一份机器可读的 skill 依赖合同，明确每个 hat 执行时依赖哪些 skill。Bootstrap、preset review 和启动前检查共同使用这份合同，提前发现依赖缺失和无人值守不适配，避免 loop 跑到对应 hat 时才失败。

核心要求：**依赖要列清楚，缺失要突出提示并阻止启动，安装后还要确认适合无人值守。**

## 合同归属与内容

- 合同属于 preset，优先放在 preset YAML 内；也可由 preset 显式关联独立 YAML/JSON。具体形式及字段名留到设计阶段确定。
- 合同是依赖声明的唯一事实来源，各检查流程复用它，不能分别维护不同清单。
- 明确 skill 与使用它的 hat 的对应关系、用途、必需或可选属性，以及加载／使用时机。
- 明确依赖的来源、解析位置和安装指引，并覆盖必需的配套 skill、引用文件及工具条件。
- 明确无人值守要求、所需输入和适配状态。可选依赖缺失时的行为必须写清楚；必需依赖不得静默降级。

## 必须满足的行为

### 1. 启动前检查依赖

启动前依赖检查必须按合同核对当前项目执行环境：依赖是否存在且完整、是否启用、对应 hat 和实际 backend 是否能够加载。

必需依赖不满足时，检查失败并阻止 loop 启动。错误信息必须突出缺失或不可用项，说明受影响的 preset／hat、用途、失败原因，以及安装或修复方式。修复后可重新检查。

“已安装”以执行环境中实际可解析、可加载为准。当前内嵌的 `ralph-html*` 可由二进制提供；外部 skill 必须在合同允许的位置解析。机器上存在同名文件不能直接视为满足依赖。

此处的检查指 loop 启动前的依赖检查，需要与已有事件提交 precheck gate 区分。

### 2. 安装后检查无人值守适配

文件存在不等于适合无人值守。检查应识别必须等待用户回答、手工操作、交互式登录、工具不可用，以及输入不足时无法继续等问题。

无人值守适配不能只依赖一个自声明标记。应结合正文审查与必要的无交互验证；审查结果关联被检查的内容版本，内容变化后需重新确认。

必需 skill 未完成适配，或适配所需输入／工具不满足时，不得作为已就绪状态启动。

### 3. 支持 skill 与 preset 的适配闭环

发现不适配时，应明确需要安装、补充输入、改造 skill，还是调整 preset。支持维护可追踪来源的项目适配版本，明确默认决策、人工参与边界和失败／停止行为。

适配影响 hat 的输入、输出或执行顺序时，必须同步修改 preset 与依赖合同，随后重新检查。不能在运行时擅自跳过原 skill 要求的人工确认。

### 4. 纳入编排及 Bootstrap 流程

| 流程 | 必须承担的职责 |
|---|---|
| Preset 起草／编排 | 声明依赖、关联 hat，明确加载时机和无人值守要求 |
| Project bootstrap | 盘点项目环境，突出缺失依赖并建议安装，列出适配待办 |
| Bootstrap review／preset review | 检查合同是否漏项、依赖是否可用、无人值守适配是否成立 |
| 安装／适配完成后 | 重新验证依赖完整性与适配状态 |
| Loop 启动前 | 执行硬门禁，必需条件不满足则阻止启动 |
| Hat 激活与执行 | 按合同提供加载指令或注入内容；加载失败走明确失败路径 |

起草和 review 还应检查 hat instructions 实际引用的 skill 是否遗漏于合同，避免清单齐全但声明不完整。

## 注重点与边界

- 优先保证检查真实可用性，诊断信息能指导用户完成安装和修复。
- 区分“存在”“可加载”“适合无人值守”“按时使用”，不能以其中一项代替其他项。
- 短小且影响全程的规则可在 hat 激活时注入；阶段性长文档可按需加载，但触发时机必须明确。
- 语义适配主要在编排和 review 阶段完成，运行时负责检查条件并执行门禁。
- 首期不要求完整包管理平台或自动安装；必须提供明确安装指引及复查入口。
- 后续实现需同步评估 preset author/review、bootstrap 操作规程及 agent-facing skill 指南，按各自作用域更新。

## 验收标准

1. 从 preset 合同可以明确回答：哪个 hat 在什么时机需要哪个 skill，以及如何满足依赖。
2. 删除、禁用必需 skill，或令其对目标 hat／backend 不可见，启动前检查均失败，并给出针对性修复提示。
3. 配套文件或间接必需依赖缺失时不能通过检查；合规的内嵌 skill 不要求重复安装。
4. 已安装但必须等待人工参与的 skill，能够在 bootstrap/review 中被指出；适配未完成时不能视为可无人值守运行。
5. 安装、补齐条件或完成适配后，重新检查能够通过；skill 内容改变后不会无条件沿用旧适配结论。
6. Bootstrap、review、启动检查和 hat 使用方式与同一份合同一致，未声明的实际依赖能在编排审查中被发现。
