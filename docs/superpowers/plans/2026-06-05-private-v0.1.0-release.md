# Private v0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `pittcat/ralph-orchestrator` private fork 上以 `v0.1.0` 发一次"自己可见"的 release，CI 在 fork 上保持绿色，不发布到公共 npm/crates.io。

**Architecture:** 复用现有 cargo-dist 配置；用 GitHub repository variable `PUBLIC_RELEASE` 作为 publish job 的统一开关（默认不存在 → publish job 全部 skip → Actions 绿色）。本地预检 + commit + tag + push tag → CI 创建私有 GitHub Release。

**Tech Stack:** Rust workspace（9 个 crate）、cargo-dist 0.30.3、GitHub Actions。

**Spec**: `docs/superpowers/specs/2026-06-05-private-v0.1.0-release-design.md`

### Task 6: 给 release.yml 的 announce 加 PUBLIC_RELEASE gate

**Files:**
- Modify: `.github/workflows/release.yml:421`（`announce.if` 行）

- [ ] **Step 6.1: 修改 announce.if**

在 `.github/workflows/release.yml` 第 421 行，把：

```yaml
    if: ${{ always() && needs.host.result == 'success' && (needs.publish-crates.result == 'skipped' || needs.publish-crates.result == 'success') && (needs.publish-npm.result == 'skipped' || needs.publish-npm.result == 'success') && (needs.smoke-test-install.result == 'skipped' || needs.smoke-test-install.result == 'success') }}
```

改成：

```yaml
    if: ${{ vars.PUBLIC_RELEASE != 'true' || (always() && needs.host.result == 'success' && (needs.publish-crates.result == 'skipped' || needs.publish-crates.result == 'success') && (needs.publish-npm.result == 'skipped' || needs.publish-npm.result == 'success') && (needs.smoke-test-install.result == 'skipped' || needs.smoke-test-install.result == 'success')) }}
```

> 这一行的语义：`PUBLIC_RELEASE` 不为 `true` → 立即成功（私有发布不需要 announce 公共包）；`PUBLIC_RELEASE == 'true'` → 走原有"所有 publish job 都要 skipped-or-success"逻辑。

- [ ] **Step 6.2: 验证四个 job 的 gate 都生效**

```bash

```

预期看到 4 行（每个 job 各一个 `vars.PUBLIC_RELEASE` 出现），且第 4 行包含 `vars.PUBLIC_RELEASE != 'true' ||`。

## 回滚预案

如需回滚整个发版：

```bash
# 1. 删远程 tag
git push origin :refs/tags/v0.1.0

# 2. 删本地 tag
git tag -d v0.1.0

# 3. revert commit
git revert --no-edit <commit-hash>
git push origin pittcat-dev  # 这一步会推分支，仅在用户明确同意时执行

# 4. 在 GitHub UI 上删除 v0.1.0 release
#    → https://github.com/pittcat/ralph-orchestrator/releases/tag/v0.1.0 → Delete
```

> 第 3 步的 `git push origin pittcat-dev` 默认**不执行**——除非用户明确要求回滚代码到 origin（多数情况下 revert 后留在本地即可）。
